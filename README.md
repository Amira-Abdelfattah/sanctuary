# Sanctuary — Home Safety App

Flutter app for the Sanctuary smart-home safety system. Reads live
gas / voltage / current readings from the same Firebase Realtime
Database your ESP32 uploads to, shows alerts, usage, and lets users
sign in with Firebase Auth.

## Architecture

Clean Architecture, feature-first:

```
lib/
  core/                     Shared, feature-agnostic code
    constants/              Colors, text styles, spacing, Firebase paths
    theme/                  AppTheme (single source of visual truth)
    widgets/                Reusable widgets (buttons, text field, cards, status pill)
    errors/                 Failure types
    utils/                  Result<T>, validators
    routing/                RootShell (bottom-nav tab container)

  features/
    auth/
      domain/               Entities, repository contract, usecases
      data/                 Firebase Auth datasource + repository impl
      presentation/         AuthProvider, LoginPage, SignupPage
    dashboard/
      domain/               SensorReading entity, repository contract
      data/                 Firebase RTDB datasource + model + repository impl
      presentation/         SensorProvider, HomeDashboardPage, hero card widget
    alerts/                 Alerts derived live from SensorReading
    usage/                  Live power stats + session trend chart (fl_chart)
    profile/                Profile page, logout

  shared/widgets/           AppBottomNavBar (used by RootShell)
  main.dart                 Composition root — wires Firebase into repositories
  firebase_options.dart     Generated by `flutterfire configure` (see below)
```

**Why this shape?** Every feature is split into `domain` (pure Dart,
no Firebase import), `data` (the only place allowed to import
`firebase_auth` / `firebase_database`), and `presentation` (Provider +
widgets). If you ever swap Firebase for a custom backend, you only
touch the `data` folders — `domain` and `presentation` don't change.

## 1. Prerequisites

- Flutter 3.24+ (`flutter --version`)
- A Firebase project — use the SAME one your ESP32 already uploads
  to (`sanctuary-e2f50`), so the app reads the exact data your device
  writes.

## 2. Connect this project to your Firebase project

The app currently ships with a **placeholder** `lib/firebase_options.dart`.
Generate the real one:

```bash
dart pub global activate flutterfire_cli
flutterfire configure --project=sanctuary-e2f50
```

Select the platforms you want (Android / iOS / Web). This overwrites
`lib/firebase_options.dart` with your real apiKey/appId values and
registers the app in the Firebase console automatically.

## 3. Enable Firebase Auth

In the Firebase console → **Authentication** → **Sign-in method** →
enable **Email/Password**. That's the only provider this app wires up.

## 4. Realtime Database rules (for testing)

Your ESP32 already writes to `/data`. For the app to also read it
while you're logged in, a minimal starter rule set:

```json
{
  "rules": {
    "data": {
      ".read": "auth != null",
      ".write": "auth != null"
    },
    "users": {
      "$uid": {
        ".read": "$uid === auth.uid",
        ".write": "$uid === auth.uid"
      }
    }
  }
}
```

(Your ESP32 currently authenticates with a legacy database secret, so
its writes bypass these rules — this only restricts the *app's* access.)

## 5. Install & run

```bash
flutter pub get
flutter run
```

## 6. Where the sensor data comes from

`lib/core/constants/firebase_paths.dart` lists every key the app
reads (`data/gas_level`, `data/voltage`, `data/current`,
`data/gas_alert`, `data/voltage_alert`, `data/current_alert`,
`data/relay_active`, `data/status`, `data/alarm`). These match
**exactly** what the ESP32 sketch writes via `Firebase.setXxx(...)` —
if you rename a key on the device, rename it in that file too.

## 7. Extending

- **New feature** → copy the `dashboard/` folder structure
  (`domain/data/presentation`) as a template.
- **New reusable widget** → put it in `lib/core/widgets/` if it's
  generic, or `lib/shared/widgets/` if it's app-shell-specific.
- **Persisted alert history** (not just live state) → add a
  `alerts/data` layer that writes to `FirebasePaths.userAlertsHistory(uid)`
  whenever `AlertsBuilder` detects a new critical alert; the domain/
  presentation layers already leave room for that without changes.
- **Onboarding screens** — the Stitch design included 3 onboarding
  slides; they weren't wired into the app yet (LoginPage is the first
  screen after splash). Add `features/onboarding/presentation/pages/onboarding_page.dart`
  and show it before `LoginPage` for first-time users if you want them.
